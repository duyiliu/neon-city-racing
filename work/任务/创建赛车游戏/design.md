## 背景

### 需求背景

创建一款具有经典开放城市赛车 MMORPG 氛围、但使用原创品牌与素材的浏览器游戏。首要目标是先验证“高速穿城、漂移、氮气与任务路线”是否好玩，再逐步扩展成长、改装和在线系统。

### 目标

- 浏览器直接运行的 3D 驾驶原型。
- 具备城市自由驾驶、手刹漂移、氮气和限时检查点任务。
- 建立可持续扩展的模拟、渲染、输入和 UI 边界。

### 非目标

- 首版不实现 MMO 后端、账号、商城和多人同步。
- 不复刻《光线飞车 / RayCity》的地图、品牌、车辆、UI 或素材。
- 首版不追求写实车辆物理与完整碰撞系统。

## 范围

- 本次做：程序化城市、街机车辆模型、追车镜头、漂移、氮气、检查点、倒计时、任务结算、响应式 HUD、暂停与重置。
- 本次不做：联网、改装、NPC 交通、存档、外部 GLB 美术资产、音频。

## 设计

### 整体链路

键盘输入映射为驾驶动作，车辆模拟产生位置、速度、朝向、漂移和氮气状态；任务模拟根据车辆位置推进检查点和倒计时；渲染适配层同步车辆、镜头、光门与 HUD。

### 模块职责

- `src/game/`：输入、纯数据模拟、任务和路线内容。
- `src/render/`：Three.js 场景、城市、车辆、光门、镜头及渲染循环。
- `src/ui/`：DOM HUD 与暂停交互。
- `work/`：跨会话设计与验证状态。

### D1 技术栈

使用 TypeScript + Vite + Three.js。首版车辆采用可控的街机模拟，避免在驾驶手感尚未验证时引入复杂刚体调参；当加入 NPC 交通、跳跃与复杂碰撞后，再接入 Rapier。

### D2 美术路线

首版用程序化低多边形几何形成一致的霓虹都市风格，不依赖外部素材。正式资产采用 GLB/glTF 2.0，并单独建立碰撞代理与 LOD。

## 接口/交互

- 键盘：WASD/方向键驾驶，Space 漂移，Shift 氮气，Esc 暂停，R 重置。
- 目标：依次通过七个光门，在倒计时结束前完成城市路线。

## 影响与风险

- 影响模块：游戏模拟、WebGL 渲染、DOM HUD。
- 兼容性：目标为支持 WebGL2 的现代桌面与移动浏览器；移动端当前仅适配显示，未提供触控驾驶。
- 回滚方式：删除项目目录即可，不修改外部系统。
- 风险点：程序化城市缺乏实体碰撞；复杂设备上的 WebGL 性能仍需实测。
